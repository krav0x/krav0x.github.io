Transformer Classification, Portugal-Wide

The dissertation is covered by a non-disclosure agreement with the industry partner. The write-up below stays at the level of methodology and architectural choices; concrete numbers, datasets, and figures cannot be shown here.

01 · Context

Context

The task was multiclass classification with heavily imbalanced classes on a large Portugal-wide dataset. Class frequency spanned several orders of magnitude, which meant that a single pooled metric would collapse to whatever the majority class looked like: any model that always predicted the majority would score well on paper and be useless in practice. Reporting had to be per-class and stratified from the start, or it would hide the model's real behaviour on the minority classes that actually mattered.

02 · Approach

Approach

Adapted a Transformer architecture from the literature to the multiclass task, keeping the attention-over-history structure and swapping the output head for a softmax over the class labels. In parallel, built a controlled baseline with the same input features and evaluation layout, so the Transformer's gains could be attributed against a like-for-like comparison rather than against an arbitrary benchmark.

Evaluation is per-class and stratified, not pooled. A single pooled metric would let the majority class dominate and hide what actually matters.

03 · Engineering notes

Engineering notes

  • Reference-implementation audit. The upstream Transformer implementation the work started from carried several correctness issues in the training and evaluation code. Time was spent isolating and fixing these before any comparison against the baseline was defensible; otherwise the Transformer's numbers would have been reporting bugs rather than model quality.
  • Baseline you can trust. The baseline was built with the same input pipeline and evaluation setup as the Transformer, on purpose. Any measured delta comes from the model, not from feature-leakage or eval-shape differences between the two paths.
  • Per-class stratified reporting. Results are reported per class, not pooled. Pooling averages away the exact structure that a heavily imbalanced dataset would collapse: whether the model actually recognises the rare classes or is quietly leaning on the majority.

04 · Stack

Stack

PyTorch. Transformer architecture adapted from the literature. Per-class stratified evaluation harness. Specific tooling, dataset, application domain, and metrics are under NDA.
